# NNUE 靜態局面數據標記評估報告

本報告針對西洋棋代理人 `d8` 訓練自訂 NNUE 模型所需之標記數據進行小規模生產測試，以評估其**生成速度（時間成本）**、**局面品質**與**資料庫容量需求**。

---

## 一、 核心評估結論
1. **生成速度極快**：在 Apple M4 (8 Workers) 環境下，靜態局面的標記速度達到 **748.94 PPS (Positions Per Second)**。
   - 生產 **250 萬 (2.5M)** 個局面（適用於 FT-128 結構）僅需 **~56 分鐘**。
   - 生產 **500 萬 (5.0M)** 個局面（適用於 FT-256 結構）僅需 **~1.85 小時**。
2. **嚴格的 Quiet Position 篩選**：我們實施了「上一步非 capture、非 promotion，且當前不在 check 狀態」的過濾條件。此條件下的 quiet 局面佔總步數的 **49.46%**。這能確保 NNUE 評估函數專注於靜態形勢，而將戰術吃子留給 Search 與 Q-search 處理。
3. **高品質的分數分佈**：小規模標記 1,000 個局面的結果顯示：
   - 均值為 **+19.90**，中位數為 **+14.0**，標準差為 **135.95**。
   - 分數絕大多數集中於 **[-200, 200]** 之間（約 25th 到 75th 百分位數為 -36.5 到 +64.0）。
   - 有效率達 **99.90%**（過濾掉極端大於 2000 或小於 -2000 的大勝大敗局）。這種局勢均衡但有細微優劣的數據，最有利於 NNUE 學習位置與子力協同。

---

## 二、 詳細測試數據

### 1. 不同 Worker 數量下的速度對比 (M4 晶片)
我們測試了不同平行 Stockfish 線程數（使用 5ms / d10 搜尋限制）的處理效率：

| 平行線程數 (Workers) | 總花費時間 (s) | 標記速度 (PPS) | 效率備註 |
| :--- | :--- | :--- | :--- |
| **4 Workers (預熱 100 筆)** | 0.96s | 104.22 PPS | - |
| **8 Workers (主測試 1000 筆)** | 1.56s | **748.94 PPS** | **最佳配置 (吞吐量最高)** |
| **12 Workers (對比測試 300 筆)** | 0.95s | 317.41 PPS | 超過實體核心數，競爭激烈導致變慢 |
| **16 Workers (對比測試 300 筆)** | 1.30s | 231.37 PPS | CPU / I/O Overhead 過高 |

> [!TIP]
> 實測顯示 **8 Workers** 為 M4 晶片上的最優平行度。超過這個線程數會因為系統啟動/關閉 Stockfish 進程的開銷與核心爭奪而降低整體 PPS。

### 2. 局面品質與分數分佈 (N = 1000)
- **有效率**：100% 局面均成功被 Stockfish 評估，其中僅 1 筆局面分數超出 `[-2000, 2000]` 的合理區間（99.90% 有效）。
- **統計指標（Centipawns）**：
  - **最小值**：-575 cp (黑方大優)
  - **25th 分位數**：-36.5 cp
  - **中位數**：+14.0 cp
  - **75th 分位數**：+64.0 cp
  - **最大值**：+683 cp (白方大優)
  - **平均值**：+19.90 cp
  - **標準差**：135.95 cp

> [!NOTE]
> 數據分數分佈非常健康，平局附近有著豐富的梯度，這對於 NNUE 來學習微調局面評估（如兵形、王安全度、控制力）是極佳的肥料。

- **解決方案**：
  我們已經實作了 [download_more_data.py](file:///Users/Shared/%E8%A5%BF%E6%B4%8B%E6%A3%8B%E4%BB%A3%E7%90%86%E4%BA%BA/rl_starter_11/agents/d8/scratch/download_more_data.py)。
